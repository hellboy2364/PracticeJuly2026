# Visualization of Parametric Curves — WinForms + Bridge/Decorator/Composite

Учебный проект на C# (.NET Framework 4.8, Windows Forms), выполненный командой из трёх практикантов в рамках летней производственной практики (июнь–июль 2026). Приложение строит параметрические кривые (отрезки и кубические кривые Безье), отрисовывает их на экране в двух визуальных стилях одновременно, позволяет собирать из отдельных кривых цельные составные траектории и экспортирует результат в SVG.

Ветка [`st-1-draft`](../../tree/st-1-draft) содержит полную, интегрированную версию проекта — все слои, описанные ниже, работают вместе в одном приложении.

## Возможности

- Генерация случайных отрезков и кубических кривых Безье.
- Одновременная отрисовка всего набора кривых в двух независимых визуальных стилях (сплошная зелёная линия со стрелкой на конце / пунктирная чёрная линия с квадратными маркерами) на двух `PictureBox`.
- Перемещение последней добавленной кривой в точку клика мышью.
- Разворот (реверс) направления последней добавленной кривой.
- Автоматическая «привязка» новой кривой к концу предыдущей — так из отдельных сегментов складывается непрерывная траектория.
- Сцепление трёх случайных кривых в одну цельную составную кривую с автоматическим выравниванием стыков.
- Экспорт текущего набора кривых в векторный SVG-файл.

## Архитектура и паттерны проектирования

Проект — это витрина нескольких классических паттернов GoF, применённых к одной предметной области: параметрические кривые и их отображение.

### 1. Геометрическая модель

Общий контракт для любой кривой — интерфейс `ICurve` с единственным методом `GetPoint(double t, out IPoint p)`, где `t ∈ [0, 1]`. Точка описывается интерфейсом `IPoint` (`X`, `Y`) и его реализацией `Point`.

Абстрактный класс `ACurve` реализует `ICurve` и берёт на себя общую часть (хранение опорных точек, сборку итоговой точки), оставляя вычисление координат (`CountX`, `CountY`) абстрактным — классический **Template Method**. От него наследуются:

- `Line` — линейная интерполяция между двумя точками;
- `Bezier` — кубическая кривая Безье по четырём точкам.

Такой минимальный контракт позволяет всем остальным слоям (декораторам, компоновщику, отрисовке) работать с любой кривой одинаково, не зная о её конкретном типе.

### 2. Визуализация (`Bridge` → обёртывание `ICurve`)

Слой визуализации разделяет *как вычисляется кривая* и *как она отображается*. Изначально это было сделано классическим шаблоном **Bridge**: отдельный интерфейс-Implementor с операциями отрисовки принимался абстракцией параметром. Позже от отдельного интерфейса отказались как от избыточного и переработали механизм — сейчас `AVisualCurve` (`Classes/AVisualCurve.cs`) хранит обёрнутую кривую (`ICurve _curve`) и делегирует ей `GetPoint`, то есть использует ту же идиому обёртывания, что и геометрические декораторы. Поверх этого `AVisualCurve` определяет шаблонный метод `Draw()` — линеаризацию кривой на 20 отрезков — и оставляет операции `DrawLine`/`DrawStartPoint`/`DrawEndPoint` абстрактными.

Конкретные визуальные стили — прямые наследники `AVisualCurve` (`Bridge/`):

- `BlackRealization`, `GreenRealization` — отрисовка средствами GDI+ (`System.Drawing.Graphics`), объект `Graphics` передаётся через вспомогательный класс `Options`;
- `BlackRealizationSVG`, `GreenRealizationSVG` — тот же алгоритм обхода кривой, но вместо вызовов `Graphics` накапливают в `StringBuilder` строки XML-разметки SVG.

`BuilderSVG` (`Classes/BuilderSVG.cs`) собирает итоговый SVG-документ из списка кривых, выбирая нужный SVG-стиль и добавляя определение `<marker>` для стрелки.

### 3. Геометрические трансформации (`Decorator`)

Абстрактный класс `Decorator` (`Decorator/Decorator.cs`) оборачивает `ICurve` и реализует тот же интерфейс, добавляя поведение поверх делегирования `GetPoint`. Конкретные декораторы:

- `Fragment` — выбирает под-диапазон `[tStart, tEnd]` исходной кривой; при `tStart > tEnd` фактически разворачивает направление кривой;
- `MoveTo` — сдвигает кривую так, чтобы она начиналась в заданной точке.

Поскольку декораторы прозрачно реализуют `ICurve`, их можно накладывать друг на друга и передавать в слой визуализации без каких-либо изменений на его стороне.

### 4. Композиция кривых (`Composite`)

`Chain` (`Composite/Chain.cs`) склеивает две кривые в одну непрерывную `ICurve`, отображая `t ∈ [0, 0.5]` на первую кривую, а `t ∈ (0.5, 1]` — на вторую. `CompositeHelp.Generate` использует `Chain` дважды и `MoveTo` для автоматического выравнивания, склеивая три кривые в одну составную траекторию.

### 5. Пользовательский интерфейс

`Form1` связывает все слои воедино: генерирует кривые, оборачивает их декораторами по действиям пользователя и передаёт получившийся список в `DecoratorHelper` (`Decorator/DecoratorHelper.cs`), который перерисовывает весь набор кривых сразу в обоих стилях на двух `PictureBox`.

## Технологии

- C#, .NET Framework 4.8
- Windows Forms
- GDI+ (`System.Drawing`) — отрисовка на экране
- Ручная генерация SVG (XML через `StringBuilder`, без сторонних библиотек)

## Сборка и запуск

Потребуется Windows и Visual Studio 2019/2022 (или MSBuild) с установленным .NET Framework 4.8 Developer Pack.

```bash
git clone https://github.com/hellboy2364/PracticeJuly2026.git
cd PracticeJuly2026
git checkout st-1-draft
```

Далее:

1. Открыть `Practice/Practice.sln` в Visual Studio.
2. Дождаться восстановления NuGet-пакетов (Serilog и зависимости) или выполнить `nuget restore` вручную.
3. Собрать решение (`Build → Build Solution`) и запустить (`F5`) — стартует главное окно `Form1`.

## Как пользоваться приложением

| Элемент управления | Действие |
|---|---|
| **Генерация кривых** | Добавляет в сцену новую случайную кривую (отрезок или кривую Безье). |
| **Сцепление** | Генерирует три случайные кривые и склеивает их в одну непрерывную составную кривую. |
| **Привязка** (флажок) | Если включён, каждая новая кривая/цепочка автоматически сдвигается так, чтобы начинаться в конце предыдущей — так набирается один непрерывный путь. |
| **Поменять местами** | Разворачивает направление последней добавленной кривой. |
| Клик по любому из полей отрисовки | Переносит последнюю добавленную кривую так, чтобы она начиналась в точке клика. |
| **Сохранить Line в SVG** / **Сохранить Bezier в SVG** | Экспортируют текущий набор кривых в SVG-файл через диалог сохранения (по умолчанию предлагаются имена `green.svg` и `black.svg` соответственно). |

Оба поля отрисовки всегда показывают один и тот же набор кривых — просто в двух разных визуальных стилях, чтобы наглядно продемонстрировать независимость геометрии от способа отображения.

## Экспорт в SVG

SVG формируется вручную, без сторонних XML-библиотек: тот же алгоритм линеаризации, что и для экрана, но вместо вызовов `Graphics` накапливает строки разметки (`<line>`, `<circle>`/`<rect>`). Стрелка на конце кривой рисуется через встроенный SVG-механизм `<marker orient="auto">`, который сам ориентируется по направлению последнего сегмента — это особенно важно для кривой Безье, конец которой направлен под произвольным углом. При форматировании чисел явно используется `CultureInfo.InvariantCulture`, иначе на системе с русской локалью дробная часть координат записывается через запятую и файл становится невалидным XML.

## Команда

Проект выполнен командой из трёх практикантов; работа была разделена по слоям архитектуры:

- геометрическая модель кривых и их визуализация на экран/в SVG (`Interface1`, `Classes`, `Bridge`) — Максим Солодун;
- геометрические декораторы и компоновка кривых (`Decorator`, `Composite`) — второй участник команды;
- пользовательский интерфейс на Windows Forms, связывающий слои воедино (`Form1`) — третий участник команды.

> Репозиторий ведётся в связке веток `st-N-draft` / `st-N-main` — по паре на каждого практиканта, так как отчёт по практике сдаётся индивидуально. Кодовая база во всех `draft`-ветках при этом общая, совместно разработанная.
